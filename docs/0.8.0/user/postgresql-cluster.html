PostgreSQL cluster

A PostgresqlCluster is a Patroni primary with streaming standbys on kcoreOS nodes. Members run as host services, not in a VM and not on Kubernetes. Patroni and etcd own unplanned failover; the controller owns planned changes (create, update, upgrade, switchover, scale).

For a single database on one node, use PostgreSQL. A node cannot host both a single-node Postgresql and a cluster member.

What you get

  • One writable primary and one or more standbys (typical lab shape: three members).
  • etcd voters on the members (odd count). Patroni holds the leader key; a lost primary promotes a standby without the controller.
  • Optional writer VIP (keepalived) that follows Patroni /primary.
  • TLS for PostgreSQL, replication, etcd, and the Patroni API from the cluster CA.
  • ClusterUpdate waits for a safe Patroni switchover before rebooting a member that still leads.

Declare a cluster

kctl pg-cluster plan -f orders.yaml
kctl pg-cluster apply -f orders.yaml --confirm

kctl apply -f also routes kind: PostgresqlCluster.

kind: PostgresqlCluster
metadata:
  name: orders
spec:
  package: postgresql_17
  members:
    - nodeId: node-a
      role: primary
      advertiseAddress: 192.168.40.103
      iface: enp6s0
      dataVolume:
        name: pg-orders
        storageClass: lvm
        volumeGroup: vg_kcore
        sizeBytes: 107374182400
        fsType: xfs
    - nodeId: node-b
      advertiseAddress: 192.168.40.143
      iface: enp6s0
      dataVolume:
        name: pg-orders
        storageClass: lvm
        volumeGroup: vg_kcore
        sizeBytes: 107374182400
        fsType: xfs
    - nodeId: node-c
      advertiseAddress: 192.168.40.145
      iface: enp6s0
      dataVolume:
        name: pg-orders
        storageClass: lvm
        volumeGroup: vg_kcore
        sizeBytes: 107374182400
        fsType: xfs
  replication:
    mode: quorum
  vip:
    address: 192.168.40.160/24
    virtualRouterId: 61
  clientNetworks: [192.168.40.0/24]
  databases:
    - name: orders
      owner: app
  roles:
    - name: app
      login: true

Use provider kcorehypervisor/kcore 0.8.0. Prefer kctl pg-cluster for the first apply until Terraform coverage for PostgresqlCluster matches the CLI.

postgresql-cluster is an alias of pg-cluster. MCP and the dashboard cover the same kind.

Failover

Patroni decides unplanned failover through etcd. The controller does not promote a standby on its own. That keeps a split-brain promotion from happening when controllers disagree across a partition. Planned switchover and every rolling change go through controller operations that call Patroni’s REST API on the node.

Default replication with two or more standbys is quorum (RPO 0 for acknowledged commits). Watchdog defaults to off on hypervisor hosts so a hung Patroni does not reboot every guest; the writer VIP and sync quorum limit damage instead.

Limits

  • One PostgreSQL cluster per node. Ports default to postgres 5432, Patroni 8008, etcd 2479/2480 (away from Kubernetes 2379/2380).
  • Package attribute must be versioned (postgresql_17, not bare postgresql).
  • Major upgrades have a write downtime window; plan states it before you confirm.
