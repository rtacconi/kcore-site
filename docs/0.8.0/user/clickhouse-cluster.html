ClickHouse cluster

ClickhouseCluster is the bare-metal design for ClickHouse on kcoreOS: shards, replicas, and ClickHouse Keeper, declared like Kubernetes and PostgreSQL and driven by the controller over gRPC.

Not in public 0.8.0. This page describes the intended operator surface. There is no module, API, or kctl clickhouse on the published tag yet. Do not plan a production migration on this page alone.

Intended shape

  • Replicas run clickhouse-server on kcoreOS nodes; Keeper is a Raft ensemble (1, 3, or 5 voters).
  • Rolling ops keep one healthy replica of each shard and Keeper quorum.
  • Same pattern as other host services: Nix owns packages and units; the controller owns membership and secrets; the agent rebuilds and runs local admin.

Example manifest (design)

kind: ClickhouseCluster
metadata:
  name: analytics
spec:
  package: clickhouse
  shards:
    - shardName: "1"
      replicas:
        - nodeId: node-a
          advertiseAddress: 192.168.40.105
          iface: enp6s0
        - nodeId: node-b
          advertiseAddress: 192.168.40.106
          iface: enp6s0
  keepers:
    - { nodeId: node-a, advertiseAddress: 192.168.40.105, iface: enp6s0 }
    - { nodeId: node-b, advertiseAddress: 192.168.40.106, iface: enp6s0 }
    - { nodeId: node-c, advertiseAddress: 192.168.40.108, iface: enp6s0 }
  clientNetworks: [192.168.40.0/24]
# Planned verbs once shipped:
# kctl clickhouse plan|apply|get|health|scale|delete
