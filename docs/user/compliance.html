Compliance enablement

← User documentation

kcore is infrastructure software. Your organisation owns compliance scope for how you deploy it (GDPR, SOC 2, PCI DSS, sector-specific rules, etc.). kcore is designed to be a compliance-enabling platform: it provides controls, APIs, and isolation properties your assessors can test, similar in spirit to shared-responsibility models used by public clouds.

kcore itself is not a substitute for your own certifications. You inherit platform controls and document your policies, processes, and workloads on top.

Encryption and identity

  • Management-plane traffic uses mutual TLS between kctl, the controller, and node agents, with cluster-issued client certificates.
  • gRPC methods enforce caller identity from certificate subject (e.g. operator vs node roles).

Workload isolation

Each VM runs under Cloud Hypervisor with dedicated KVM context, network interfaces, and disks. This separation is the basis for tenancy and cardholder/workload boundaries in your architecture.

Declarative, auditable hosts

NixOS configurations are reproducible and versioned; system generations support rollback. Changes flow through declared config rather than ad hoc shell edits on production hosts.
