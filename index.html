One platform, several jobs

The same cluster runs the private cloud, the edge rack, and the GPU box.

Private cloud in a datacenter

Three or more hosts, shared Ceph, VMs that restart on another host when one dies, and live migration to empty a node for maintenance.

Leaving VMware or Proxmox

Priced per CPU socket, not per core. Windows guests run next to Linux. kcore-migrate inventories the estate and converts exported disks. A hosting provider facing the VCSP end date can ask for an estate assessment below.

Edge and remote sites

The host is immutable. An update soaks on one node first and a failed boot returns to the previous generation without a call-out. Provisioning brings a rack up over the BMC.

GPU and AI work

Whole-GPU passthrough, NVIDIA vGPU slices, and Slurm clusters as host services. A model can drive the cluster through MCP.

Kubernetes and databases

Kubernetes clusters on kcore nodes with Cilium and local or Ceph storage. A PostgreSQL database is one manifest.

Sites that have to prove things

mTLS on every call, roles, an append-only audit log, a compliance report, an SBOM, and immutable backups that a stolen credential cannot delete.

What is in the box

Everything here ships in 0.7.0. Limits are listed further down.

Updates that roll back

kctl update version set v0.7.0 updates one canary node, compares it with the rest, then moves on one node at a time. A node that fails its health check boots the previous generation.

HA for VMs

A host that stops heartbeating is fenced at the storage layer, then its VMs restart on the survivors by priority. Anti-affinity and admission control are built in.

Live migration

Cloud Hypervisor streams memory over TCP while both hosts map the same Ceph image. Drain a node and its VMs move.

kcore SAN on Ceph

A CephCluster resource builds the cluster: encrypted OSDs, a replicated pool, RBD disks, snapshots, and member removal that waits for the data to move.

Dashboard

Sign in with a password and TOTP. VMs, nodes, storage, releases, HA events, and a serial console in the browser. Every page names its kctl command.

API, Terraform, YAML

One controller API behind kctl, the dashboard, and a Terraform provider with resources for VMs, networks, Ceph, Kubernetes, ingress, updates, and backups.

MCP and an AI agent

Editors speak MCP. kctl agent is a chat page in the binary. Both ask, show a plan, and change nothing until you approve.

GPUs

Name a GPU and give it to a VM. Slice an NVIDIA card into vGPUs. Cold migration lands the guest on a free card of the same family. Intel and AMD SR-IOV slices use the same manifest and are not yet run on lab hardware.

Windows, Linux, containers

Windows Server and desktop guests, Linux guests, OCI containers on a node, and Kubernetes clusters, managed with the same tools.

Where the edges are

Read these before you plan a move.

Needs shared storage

  • Live migration and failover need the disk on Ceph.
  • A ZFS VM with a current replica restarts on its replica node. Other local disks stay on their host.
  • Devices passed through with VFIO do not live-migrate. Intel and AMD vGPU slices are untested on hardware.

Operations

  • Dashboard sign-in is password and TOTP. There is no SSO yet.
  • Update bundles for air-gapped sites are designed, not shipped. Use a tag mirror.
  • A 0.6.x cluster takes one hand-written update to reach 0.7.0.

Migration

  • kcore-migrate inventories vCenter and Proxmox and converts exported disks. It does not read disks straight from vCenter.
  • Moving a whole estate is still a project. We run it with you.

How it works

A controller holds desired state; node agents run Cloud Hypervisor on each NixOS host; you operate the cluster with kctl and the same gRPC APIs.

  • ✓
    Immutable OS

    Built on NixOS. The host filesystem is read-only. Updates swap the entire system atomically.

  • ✓
    API-First

    gRPC all the way down. The CLI and Terraform provider are just API clients.

  • ✓
    Multi-Node

    Add nodes by booting the ISO and pointing them at the controller. They register automatically.

  • ✓
    Flexible Storage

    Local directories, LVM, or ZFS on the host. Ceph is the shared-disk option.
