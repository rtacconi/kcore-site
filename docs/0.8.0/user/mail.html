Mail server

kcore.mail turns a kcoreOS host, or a NixOS VM on kcore, into a mail server with Stalwart: SMTP in and out, submission, IMAP, optional ManageSieve, spam filtering, DKIM/SPF/DMARC, and a web admin. nginx terminates HTTPS and obtains a Let’s Encrypt certificate.

Prefer a dedicated VM with its own public IP and PTR. Do not share a failure domain with the hypervisor cluster that hosts production guests.

Architecture

  • One Stalwart process replaces the usual Postfix/Dovecot/Rspamd stack (services.stalwart from the pinned nixpkgs).
  • nginx owns HTTPS for the web admin and JMAP; Stalwart’s HTTP listener stays on loopback.
  • Mail, index, and directory live in one RocksDB under Stalwart’s data directory.

Enable the module

kcore.mail = {
  enable = true;
  hostname = "mail.example.com";
  extraHostnames = [ "autoconfig.example.com" "mta-sts.example.com" ];
  acme = {
    email = "postmaster@example.com";
    staging = true; # first deployment only
  };
  adminSecretFile = config.age.secrets.stalwart-admin.path;
  manageSieve.enable = false;
};

Ports

PortUse
25SMTP from other servers (provider must allow outbound 25 too)
465 / 587Submission (implicit TLS / STARTTLS)
993IMAP (implicit TLS; plain 143 is not offered)
4190ManageSieve when enabled
80 / 443ACME and HTTPS admin / JMAP

First deployment

  1. Confirm outbound port 25, set PTR for every public address to hostname, and check blocklists.
  2. Publish A/AAAA for hostname and any extraHostnames.
  3. Deploy with acme.staging = true, check stalwart and nginx, open the web admin.
  4. Switch to production ACME and rebuild.
  5. As admin, create the domain and DKIM keys, then publish MX, SPF, DKIM, and DMARC.

What Nix owns vs the web admin

Nix owns hostname, listeners, certificate paths, storage backend, and the fallback admin secret. Domains, accounts, aliases, DKIM keys, and spam tuning live in Stalwart’s database so a rebuild does not wipe mailboxes.

Limits (v1)

  • No controller or kctl resource yet; configure the NixOS module on the mail host or guest.
  • No clustered Stalwart, no declarative domains/accounts, no bundled webmail.
  • kcore uses the AGPL Stalwart package from nixpkgs and only configures it.
