kctl CLI reference

kctl is the command-line interface for managing kcore clusters. Global flags: -s / --controller (controller address, repeatable for HA), -k / --insecure (skip TLS verification), -c / --config (path to config file), --node (node address for direct node commands).

You are browsing in YAML mode. This page lists CLI commands; for manifest kinds and fields see the YAML manifest reference.

This page is the kctl reference. Terraform examples are on the task pages, such as VM creation.

create

kctl create is idempotent. Re-running the same command (or re-applying the same manifest with -f) performs a server-side upsert: it creates the resource if missing, updates mutable fields if they drifted, rejects changes to immutable fields with InvalidArgument, or prints unchanged when the stored state already matches. See Idempotency and upsert for the mutable/immutable field tables.

SubcommandDescription
vmCreate a VM from CLI flags or -f YAML manifest. Assign a GPU with --gpu radeon0.
containerCreate a container on a node
postgresqlOne PostgreSQL database from the NixOS package. Alias postgres. See PostgreSQL.
networkCreate a network
clusterInitialise PKI and mTLS context for a new cluster

kctl create vm accepts --extra-network (repeatable), --label key=value (repeatable), and --anti-affinity <group>. kctl create network accepts --ipv6-prefix, --ipv6-gateway, and --east-west-firewall. See Networks and VM creation.

operator

Operators are named RBAC identities, each with its own client certificate under CN=kctl:<name>. Every subcommand here needs cluster-admin.

SubcommandDescription
createRegister an operator identity as CN=kctl:<name>. Names are ASCII alphanumeric plus _ and -.
listList operators
getShow one operator and its roles
issue-certIssue a client certificate for the operator from the controller sub-CA and write it to ~/.kcore/operators/<name>/operator.crt and operator.key.
grant-roleGrant a role. --role is required and takes read-only, vm-admin, or cluster-admin.
revoke-roleRemove one role from an operator, named with --role.
deleteDelete an operator and all of its role assignments

Removing a role is not the same as revoking the certificate. revoke-role changes what an identity is allowed to do; the certificate itself stays valid until you revoke it with kctl revoke cert --subject kctl:<name>. Revocation takes effect on the next RPC the operator makes, not during the TLS handshake. See certificates & encryption.

SubcommandDescription
nodeCold-reassign all VMs off a node (shared RBD does not copy disks). Use --target-node to pin the destination.

migrate

SubcommandDescription
vmLive-migrate a Ceph-backed VM to --target-node. Optional --allow-cold-fallback. A VM with a GPU is cold-migrated onto a free GPU of the same family, or onto --gpu. See VM migration and GPU passthrough.
reset-sessionClear a stranded live-migrate receive session on --node (mandatory). Reports what it would clear and exits non-zero unless --force is given. Needs cluster-admin.

A receive session outlives its migration if the controller dies mid-flight, and every later migration of that VM to that node then fails with ALREADY_EXISTS. Nothing clears it automatically. Inspect first with kctl get migrate-session <vm> (read-only; queries every CephCluster member unless you pass --node), then clear with kctl migrate reset-session <vm> --node <id> --force. Clearing a session whose receive VMM is still alive kills an in-flight migration. See VM migration.

kubernetes

kctl kubernetes plans and applies a KubernetesCluster manifest. Needs cluster-admin. The API VIP, Cilium L2, and volumes are on the Kubernetes page.

SubcommandDescription
apply -f FILEPrint the plan and ask y/n, then create or update.
get NAMEPrint one cluster.
listList clusters.
health NAMEPrint control-plane, worker, etcd, and API status.
delete NAMEDelete the cluster row. --force is accepted. This does not turn Kubernetes off on the nodes.
scale NAMERecord added members as node-id:address. The orchestrator does not join them. --remove does not delete the membership row.

apply

Apply a NixOS configuration to the controller. Flags: -f (config file), --dry-run (preview without applying).

diff

Show what applying a manifest would change, without changing anything. -f / --filename is required. Only kind: DiskLayout is supported today — any other kind exits with an error rather than guessing. See Day-2 operations.

version

Print the kctl client version. Takes no flags and does not contact a controller.

console

kctl console <vm> attaches to a VM's serial console through the controller. Press Ctrl-] then Enter to detach. Needs vm-admin, and every attach is recorded in the audit log as AttachVmConsole with the actor, the VM and the timestamp.

This is a serial console, so it is the right tool for a CLI login, rescue, or watching an installer. kcore does not provide a hypervisor-level graphical console; if you need a desktop, run a VNC server inside the guest and reach it over the network. The dashboard exposes the same console in a browser.
