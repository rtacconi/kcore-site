What’s new in 0.8.2

0.8.2 adds automated Kubernetes dual-CA rotation, more day-2 Kubernetes operations (S3 etcd backups, VolumeSnapshot CSI CRDs, etcd-ready wait), and the CephCluster lifecycle and CSI work that landed after 0.8.0. Enterprise day-0 for this release is already published; the public tag follows the usual embargo.

Kubernetes dual-CA rotation

  • kctl kubernetes rotate-ca <cluster> --step begin|reissue|retire --yes replaces the cluster CA (and by default the etcd CA) without a hard cutover.
  • Nodes get a trust bundle (old then new) while --cluster-signing-cert-file stays a single active CA that matches ca.key.
  • Each step queues a control-plane-first roll. kctl kubernetes certs shows the phase and any roll still in progress. Leaf rotate-certs is refused while dual-CA is active.
  • See the expanded Kubernetes page.

Kubernetes day-2

  • In-place Kubernetes upgrades from spec.version on KubernetesCluster (not ClusterUpdate).
  • etcd backup policy on the cluster (spec.backup), including S3 targets with SigV4; kctl kubernetes backup create|list|delete.
  • VolumeSnapshot CSI CRDs are embedded in the controller and applied with the cluster.
  • Joining waits for etcd to be ready before the new member proceeds.
  • kctl kubernetes backup, rotate-certs, and related health commands round out day-2 ops.

Ceph

  • CephCluster lifecycle completion: member drain, maintenance with noout, client key and mon/dmcrypt rotation, typed health.
  • RBD and CephFS CSI for a KubernetesCluster on the same CephCluster (image pin quay.io/cephcsi/cephcsi:v3.13.1).
  • Cluster updates gate on Ceph (ok-to-stop, noout, mons first). Finalize with kctl ceph finalize-osd-release --yes.
  • See the expanded kcore SAN page.

Upgrade notes

  • From 0.8.0 / 0.8.1. Enterprise: kctl update version set v0.8.2 --channel enterprise. Community waits for the public tag, then kctl update version set v0.8.2.
  • Schema. Controller schema moves to 79 (previous CA columns and ca_roll_pending for dual-CA).
  • Dual-CA. Node agents must ship the module that accepts caSigningCrt before you run rotate-ca --step begin.
  • Back up first. Take a Vault backup of anything you cannot rebuild. For Kubernetes, take an etcd snapshot before CA rotation.

Known limits

  • Some Ceph CSI and lifecycle paths are implemented but not yet exercised live in every lab topology.
  • Update bundles for air-gapped sites are designed but not shipped.
  • Live migration does not move VFIO devices.
