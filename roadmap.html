Roadmap

Where kcore is heading. This reflects real plans from our codebase — not aspirational marketing. Items move as engineering priorities shift.

Partial Some groundwork done
In Progress Actively being built
Planned Designed, not yet started

Security & Compliance

Hardening the trust model, adding audit trails, and enabling regulated deployments.

🔐 Certificate Lifecycle

Full rotation, expiry handling, and revocation for the mTLS PKI.

  • Partial Manual cert rotation via kctl rotate
  • Planned Automated certificate rotation workflows
  • Planned CRL / OCSP revocation support
  • Planned Certificate status API (GetCertificateStatus, RotateCertificates)

🛡️ RBAC & Authorization

Moving from coarse identity-based auth to fine-grained role-based access control.

  • Planned Role definitions: read-only, vm-admin, cluster-admin
  • Planned Per-API-call authorization enforcement
  • Planned Admin-gated compliance commands

📋 Audit Logging

Append-only record of every mutating API call for compliance and forensics.

  • Planned Append-only JSON audit log with actor, action, resource, timestamp
  • Planned ListAuditEvents gRPC API with retention policies
  • Planned Webhook events for audit.event integration

📦 Supply Chain & Reporting

SBOM generation, signed releases, and compliance reporting APIs.

  • Planned Software Bill of Materials (SBOM) generation
  • Planned Signed release artifacts
  • Planned GetComplianceReport, ExportSbom, GetCryptoConfig APIs
  • Planned gRPC rate limiting

High Availability & Replication

Multi-controller clusters with CRDT-based state replication across data centres.

🔄 CRDT Replication Engine

Eventually-consistent state merge across controllers using CRDTs and an append-only replication log.

  • Partial Topology and DC identity model designed
  • In Progress Replication log, ack frontiers, and merge engine
  • Planned Cross-DC peer fan-out and anti-entropy
  • Planned Conflict resolution UX and operator tooling

⚙️ State Reconciliation

Robust reconciler for controller-to-node desired-state sync with retry and rollback.

  • In Progress Head materialisation for event-sourced state
  • In Progress Reservation model for IP and storage escrow
  • Planned Full compensation executor for domain rollback
  • Planned Generation counters and multi-node rollout coordination

🌐 Multi-Controller Failover

Nodes and kctl automatically fail over when the primary controller is unreachable.

  • Partial --dc-id and --join-controller CLI flags designed
  • Planned kctl / node-agent fallback to secondary controllers
  • Planned Scheduler operating on eventually-consistent state

📡 Webhooks & Events

Push-based event system for external integrations and monitoring.

  • Planned node.heartbeat.missed event
  • Planned cert.expiry.warning event
  • Planned node.registered, vm.state.changed events
  • Planned Configurable webhook endpoints in controller.yaml

Scheduler & Networking

Smarter VM placement and richer network capabilities.

📊 Scheduler Policies

Moving beyond basic capacity-aware scheduling to topology-aware placement.

  • Planned Label-based affinity (--label dc=dc-a)
  • Planned Anti-affinity rules for HA (avoid co-locating same-prefix VMs)
  • Planned Overcommit ratio for scheduling beyond physical capacity
  • Planned Load-aware placement using real-time node metrics

🌍 Networking

Expanding from single-NIC IPv4 to richer network topologies and controls.

  • Planned Multi-NIC / multi-homed VMs
  • Planned IPv6 support
  • Planned East-west firewall between VMs on the same bridge
  • Partial TCP/UDP port filtering (proto defined, not yet wired to kctl)
  • Planned VXLAN IP reclamation and improved peer discovery

Formal Verification

Property-based testing, model checking, and mathematical proofs for critical paths.

🧪 Property Testing & Model Checking

Phased rollout of proptest and Kani harnesses across the safety-critical codebase.

  • Planned Phase 1: proptest on Nix generation (escape round-trip, sanitisation, structural validity)
  • Planned Phase 2: Kani harnesses for nixgen and disk path validation
  • Planned Phase 3: proptest on database invariants

📐 TLA+ Specifications

Modelling distributed protocols to catch design bugs before they become code bugs.

  • Partial Bounded TLA+ specs and CI integration delivered
  • Planned ControllerNodeReconcile.tla model
  • Planned ControllerReplication.tla model
  • Planned CrossDcReplication.tla model
  • Planned Trace bridge: Rust test traces validated against TLA+ invariants

Operations & Node Lifecycle

Day-2 operational tooling and resilience improvements.

🔧 Operational APIs

New gRPC endpoints for cluster health and operational insight.

  • Planned GetClusterHealth API
  • Planned Backup and restore tooling
  • Planned ISO upload support in image workflows

🖥️ Node Lifecycle

Stronger safety around node removal and VM continuity.

  • Planned Automatic VM migration when a node becomes unreachable
  • Planned Node cordon (currently only drain is supported)
  • Planned Certificate invalidation on node deletion

Explicitly not planned

  • CSR approval flow (Kubernetes-style certificate signing requests)
  • Admission webhooks
  • Formal API versioning contract
