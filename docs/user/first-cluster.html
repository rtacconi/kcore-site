First cluster

This walkthrough creates a single-node kcore cluster: one machine running both the controller and the node agent, ready to schedule VMs.

1. Create the cluster PKI

On your operator workstation (where kctl is installed):

kctl create cluster --name prod

This generates the root CA, sub-CA, controller certificate, and kctl client certificate under ~/.kcore/prod/.

2. Boot the target machine

Boot the server from the kcore ISO. The live environment starts a node-agent listening on :9091.

3. Discover hardware

kctl --node 192.168.40.105:9091 node disks
kctl --node 192.168.40.105:9091 node nics

Identify the OS disk (e.g. /dev/sda) and any data disks.

4. Install to disk

Use --run-controller to start a controller on this node. The OS disk is partitioned with LUKS encryption (TPM2-sealed when available).

kctl --node 192.168.40.105:9091 node install \
  --os-disk /dev/sda \
  --run-controller \
  --dc-id DC1

The node reboots into the installed NixOS system. The controller listens on :9090 and the node agent on :9091.

5. Approve the node

After boot the node agent registers with its local controller and appears as pending:

kctl -s 192.168.40.105:9090 get nodes
kctl -s 192.168.40.105:9090 node approve <NODE_ID>

Pending nodes cannot schedule workloads. Approval is a human gate on top of mTLS.

6. Verify the cluster

kctl -s 192.168.40.105:9090 get nodes
kctl -s 192.168.40.105:9090 get compliance-report

The node should show status ready and approval approved.

7. Create your first VM

kctl -s 192.168.40.105:9090 create vm web-01 \
  --image https://cloud.debian.org/images/cloud/bookworm/latest/debian-12-genericcloud-amd64.qcow2 \
  --image-sha256 <sha256> \
  --network default \
  --storage-backend filesystem \
  --storage-size-bytes 42949672960 \
  --wait-for-ssh

See VM creation for all options including YAML manifests, SSH keys, and cloud-init.
